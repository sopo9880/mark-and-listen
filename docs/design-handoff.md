## 제품 목표와 화면 설계

Mark & Listen은 시험 회차를 만들고, 준비한 문항과 음원으로 오프라인에서 응시하고, 원점수와 오답을 복습하는 데스크톱 앱이다. 홈과 설정은 [Canvas Assistant](https://github.com/sopo9880/canvas-assistant)의 화면 구성을 참고하고 기존 Mark & Listen 로고를 재사용한다. 홈은 여러 시험을 수용할 수 있는 이름과 구성을 사용한다. 이어서 풀기, 새 문제 제작, 시험관, 제작 중인 회차, 최근 연습을 보여준다.

- **문제 제작** — 시험관 선택에서 시작한다. 최초 시험관은 TOEIC이다. 전체 200문항(Part 1–7, LC 100 + RC 100), 단일 파트, 복수 파트와 문항 수를 지정하는 세부 조정을 제공한다. 시험관별 파트, 출제 단위, 시간과 채점 규칙은 분리한다. Part 3·4는 각 3문항, Part 6은 4문항 단위를 지키고 Part 7은 지문과 문항 묶음을 유지한다.
- **시험 연습** — 저장된 회차 목록에서 선택해 응시한다. 전체 회차 기준으로 LC 45분과 RC 75분을 적용한다. 실전 OMR에 직접 마킹하며 시간 만료에 따라 영역을 전환하고 제출한다. 채점은 원점수 기준이며, 제출 후 정답·오답과 해설을 확인한다.
- **제작과 응시 분리** — 문항과 필수 음원이 준비되고 검수가 끝나면 응시할 수 있다. 생성이 끝나도 시험은 사용자가 시작한다. 응시는 저장된 문항·음원으로 진행하며, 기존 기록의 보존과 백업을 고려한다.

## 엔진, 음원, 패키징 설계

| 영역 | 합의한 설계와 현재 구현 범위 |
|---|---|
| 문항 생성 | 기본 엔진은 Codex다. OpenAI GPT API와 Gemini API는 독립적인 선택 옵션이다. 기본 문항 생성과 이미지 입력 모델 선택, 듣기 공급자 선택을 분리한다. |
| Codex 엔진 | Windows x64 관리형 엔진은 공식 최신 안정판을 필요할 때 내려받는다. 지정 버전 실행 파일을 설치본에 포함하지 않는다. 자동 업데이트가 기본이며 실행 중인 제작·로그인·응시를 존중한다. 교체에 실패하면 기존 동작 버전을 유지한다. 로그인은 Codex CLI의 기본 브라우저 흐름을 시작하고 상태를 재확인한다. |
| 연결 상태와 Live 선택 | 왼쪽 아래 Codex·Gemini·GPT API 상태를 미설정, 확인 전, 연결됨, 오류로 구분한다. Live 공급자는 Gemini Live 또는 OpenAI GPT Live를 사용자가 선택한다. 선택한 계정으로 모델 목록을 조회·갱신하고, 텍스트 입력과 오디오 출력을 지원하는 Live 모델을 노출하는 것이 목표다. 베타에는 공급자별 조회와 필터, 단문·연속 문장·A–D 낭독 테스트 경로가 있다. 실제 계정별 모델 노출과 OpenAI Live 동작 범위는 추가 검증이 필요하다. 무료 이용을 우선하며 공급자·모델·유료 옵션을 조용히 바꾸지 않는다. |
| Live 듣기 제작 | 낭독 지시와 실제 대본을 같은 세션 요청에 넣고 생성된 오디오와 전사를 구간별로 받는다. 설정 테스트와 회차 제작이 공통 전사 검증을 사용한다. 대소문자, 문장부호, 일부 숫자 표기와 축약형을 정규화하되 단어·숫자·부정어·순서의 의미 변경은 실패로 처리한다. 전사 불일치는 같은 공급자와 모델로 실패 구간만 최대 두 번 더 낭독한다. 통과한 오디오는 회차에 연결해 로컬에 저장한다. 검수에서 승인한 구간을 실제 시험에서 재생하고 시험 중에는 Live를 호출하지 않는다. |
| 데스크톱 패키징 | Windows x64 Tauri/NSIS 설치 EXE가 우선이다. 시스템 WebView2를 쓰며 필요 시 다운로드 부트스트래퍼를 사용한다. Tauri 설치본에는 Electron, 기본 샘플 음원, Codex 실행 파일이 들어가지 않는다. macOS DMG와 Android APK는 향후 계획이다. |
| 앱 업데이트 | 앱과 Codex 엔진의 업데이트는 별도다. 앱 표시·태그·설치 파일명은 네 자리 버전을 사용한다. 내부 npm/Tauri 메타데이터는 도구 규격에 따라 세 자리다. v0.1.0.0에서 v0.1.1.0으로는 새 설치 파일을 한 번 직접 설치한다. 이후 설정의 앱 업데이트에서 확인·승인하면 GitHub의 서명된 매니페스트와 설치 파일 해시를 검증한 뒤 설치·재시작하는 경로가 있다. |

화면과 시험 규칙은 [UI 화면 모듈](../public/ui/), [시험관 레지스트리](../public/lib/exams.mjs), [응시 상태 기계](../public/lib/attempt.mjs), [채점](../public/lib/scoring.mjs)을 참고한다. 엔진과 생성은 [Codex 관리](../src/codex-updater.mjs), [로컬 서버](../src/server.mjs), [Live 모델 조회](../src/live-models.mjs), [전사 검증](../src/narration.mjs)에 있다. 패키징과 신뢰 검증은 [스테이징](../scripts/stage.mjs), [Tauri 설정](../src-tauri/tauri.conf.json), [앱 업데이트](../src/app-update.mjs), [서명 릴리스 워크플로](../.github/workflows/release-beta-win64.yml)를 참고한다.

## Part 1 사진과 삽화

| 자산 또는 기능 | 상태 |
|---|---|
| Flow 사진 200장 ZIP | 생성·수집 후 비공개 별도 보관 중이다. 공개 저장소, 릴리스, 설치본에는 포함하지 않는다. |
| 별도 사진 6장 파일럿 | JPEG 여섯 장을 직접 선택하는 별도 코드 경로가 있다. 선택한 이미지 입력 모델에 사진 픽셀을 보내 영어 정답 하나와 오답 셋을 만들고, 후속 모델 호출에서 정답의 유일성, 모호함과 같은 장면 중복을 확인한다. JPEG 유효성 검사와 동일 바이트 중복 검사도 있다. 파일럿의 자동 검증은 모의 응답을 사용했다. |
| 설치본의 연습용 Part 1 삽화 6개 | 고정 대본을 사용하는 연습용 문항의 SVG 삽화다. 해당 경로로 얻은 결과는 Flow 사진 출제 검증에 포함하지 않는다. |
| 일반 제작에 Flow 사진 연결 | **v0.2.0.0 구현.** 앱의 ‘Part 1 사진 보관함’에서 ZIP·이미지를 가져오면 브라우저가 1200px JPEG(≤400 KB)로 정규화하고 dHash를 계산해 사용자 데이터 폴더(`photos/`)에만 저장한다. TOEIC 회차 생성 시 Part 1 자료를 ‘사진 보관함’으로 고르면 덜 쓴 사진부터, 같은 장면(파일명 유사도 또는 픽셀 해시)은 겹치지 않게 배정하고 회차 폴더에 사본을 둔다. 설정의 ‘사진 문항 엔진’(Codex `--image`, GPT API, Gemini API)이 사진 픽셀로 문항을 만들고 별도 호출로 검증한다. 엔진·키가 없으면 실패로 표시하고 삽화로 대체하지 않는다. 검증 실패한 사진은 ‘다른 사진으로 교체’로 바꿀 수 있다. 제공된 200장 ZIP(장면당 변형 2장)으로 가져오기·배정을 확인했고, 실제 비전 모델 호출은 모의 응답으로만 검증했다. |

관련 소스와 테스트는 [사진 파일럿](../src/photo-pilot.mjs), [고정 대본·삽화](../public/lib/toeic-fixed-source.mjs), [사진 파일럿 테스트](../test/photo-pilot.test.mjs)에 있다.

## 확인한 검증 결과

**공개 GitHub Actions**에서 Windows 빌드, 설치 및 실행 확인, 설치 파일 체크섬 확인, 업데이트 매니페스트 서명과 검증, 프리릴리스 게시가 통과했다. 릴리스에는 Windows 설치 EXE, SHA-256 목록, 업데이트 매니페스트와 서명이 있다. Windows Authenticode 서명은 별도이며 이 설치본에는 없다. 다음 버전으로의 실제 앱 내 업데이트와 재시작은 아직 확인하지 않았다. [실행 #45404882649](https://github.com/sopo9880/mark-and-listen/actions/runs/45404882649) · [v0.1.1.0 베타](https://github.com/sopo9880/mark-and-listen/releases/tag/v0.1.1.0)

**별도 로컬 Windows 실사용 확인**에서 아래 진행 상태를 관찰했다. 이 결과는 사진 파일럿의 mock 테스트와 구분하며, 전체 회차 완주나 검수 통과의 근거로 사용하지 않는다.

| 확인 항목 | 관찰 결과 |
|---|---|
| Codex 문항 제작 | **6/6** |
| Gemini Live 음원 | **10/24** |
| 중단 지점 | **Part 1 3번 C**에서 대본과 전사가 최초 요청과 두 번의 재낭독 모두 불일치 |
| 후속 구간 | 대기 상태 |
| 수동 음원 검수 | **0/24** |

확인된 실패는 **전사 비교 불일치**다. 당시 음성 자체의 생략·변경, 공급자 전사 오류, 구간 경계나 선택지 라벨의 처리 차이는 원인 후보로 남는다. 대본·실제 음성·전사를 나란히 비교해야 구분할 수 있다. 관찰된 수치만으로 키나 할당량 오류, 실제 낭독 누락, 특정 모델 결함을 확정할 수 없다.

**자동 검증 범위**에는 회차와 오프라인 응시 흐름, 업데이트 검증, 사진 입력과 판정, Live 프로토콜 및 전사 비교가 있다. 공급자와 모델 응답을 대체한 테스트는 해당 실계정의 동작 보장이 아니다. Windows 기본 브라우저의 Codex 로그인 완료부터 상태 갱신까지, 멀티턴 Live 전체 LC, 사진 기반 회차의 실계정 오프라인 완주는 별도 검증 항목이다. [테스트 목록](../test/)

## 남은 작업과 수용 기준

| 작업 | 수용 기준 |
|---|---|
| 일반 Part 1의 Flow 사진 출제 연결 | 로컬 사진을 선택하면 비전 입력을 지원하는 지정 모델이 실제 픽셀을 받아 문항과 A–D 대본을 생성한다. 정답 두 개, 애매한 장면, 장면 변형 중복은 거절한다. 사진이 없거나 모델을 사용할 수 없으면 이유를 표시하고 출제·준비 완료를 막는다. 사진이 필요한 회차를 삽화로 대체해 완료 처리하지 않는다. 원본 사진과 음원은 로컬에 두고 설치본에는 넣지 않는다. |
| 전사 중단과 재시도 개선 | (v0.2.0.0: 대본·전사·누락·추가 비교, 시도 횟수, 실패 구간 마지막 전사 표시 구현) 기대 대본, 실제 전사, 누락·추가·변경 구간, 시도 횟수를 검수 화면에서 비교한다. 정상 전체 낭독, 중간 표현 누락, 선택지 순서 바뀜, 끝 잘림, 대본을 달라는 응답, 숫자·부정어 변경을 구별한다. 정상 구간은 유지하고 실패 구간만 다시 생성한다. 재시작 후 실패·대기·완료 상태가 남아야 한다. |
